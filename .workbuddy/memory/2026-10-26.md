## 移动中 180° 快速转身 + 连续快速转身（已实现，编译通过）

设计文档：`Docs/Turn-180-Design.md`

### 核心结论：连续旋转不要状态，离散 pivot 才要状态

- 小/中角度：旋转提速 + 速度折扣，纯连续量，无状态，永不抖。
- 180° 反打：`PC_01_Jog_Pivot_L_180_Lfoot` / `_R_180_Rfoot` 蒙太奇（自带 root yaw）。
- **判据是"输入方向是否稳定"，不是"角度多大"**。绕圈时角速度永远不安静 → pivot 一次都不触发。

### 引擎源码核对（三条关键事实）

1. `FAnimNode_OrientationWarping::LocomotionAngleDeltaThreshold` 默认 **90°**。
   超过后节点把 `LocomotionDirection` **取反**再算 → warp 结果是 **0°，不是 90°**。
   头文件注释原话："Rather than orientation warping by 180 degrees, the system will warp by 0 degrees"。
   → Warping 在 180° 场景下**完全不工作**，这是刻意设计（摊到脊椎上会扭断腰）。
2. `UAnimInstance::RootMotionMode` 默认 `RootMotionFromMontagesOnly`（`AnimInstance.cpp:202`）。
   → 状态机的 root motion 不驱动胶囊。pivot clip 的 180° 在 root bone 里，
   **必须用蒙太奇播**，否则身体转了胶囊没转。
3. `UCharacterMovementComponent::Acceleration` 在 `ControlledCharacterMove` 里每帧赋值
   （`CharacterMovementComponent.cpp:6451`），`PerformMovement` 之后**不清零**；
   但 `GetLastMovementInputVector()` 更准 —— 是上一帧被消费的世界空间输入，
   引擎注释明说"动画更新应该用它"。

### 代码改动

`UACTCharacterMovementComponent`
- `UpdateDesiredYaw(float DeltaTime)`：目标角从**速度方向**改为**输入意图**
  （`GetLastMovementInputVector()`），松手滑行时才回落到速度。这是"转身慢半拍"的根因修复 ——
  原来要等速度掉头（0.6s）才开始转。

- `PhysicsRotation`：大角度时旋转速 Lerp 到 `SharpTurnInterpSpeed`(1080)；
  新增 **RM/传送后的朝向漂移保护**（`CurrentYawAngle` 与 actor yaw 差 >1° 就采纳 actor yaw）。
  这是**既有隐患**：之前 roll 蒙太奇带 RM 时，缓存变脏 → 下一帧 FixedTurn 把角色拽回去（回弹）。

  折扣只乘最终上限，不回写 `SmoothedMaxSpeed`（否则被插值平滑两次，恢复拖长尾）。

`AACTCharacterBase`

- `IsAnyMontagePlaying()` 守卫：翻滚/攻击中不插队（两个 RM 叠加会把胶囊转飞）。

## 追问：蒙太奇播完怎么回到状态机 + pivot clip 是三段式

用户说明 `PC_01_Jog_Pivot` 的结构是：**当前移动一段距离 → 到回转点 → 转身后继续移动一段距离**。

### 更正：蒙太奇 RM 期间不是"叠加"，是"替换"

`CharacterMovementComponent.cpp:2952-2969`：
```cpp
if (HasAnimRootMotion())
{
    AnimRootMotionVelocity = CalcAnimRootMotionVelocity(RootMotionDelta, DeltaSeconds, Velocity);
    Velocity = ConstrainAnimRootMotionVelocity(AnimRootMotionVelocity, Velocity);  // 整个替换
}
```
→ 不会双重位移（上一轮的担心是错的）；`MaxWalkSpeed` / `TurnSpeedScale` 在 RM 期间**完全无效**；
不需要手动清零速度；`PhysicsRotation` 已被 `bAllowPhysicsRotationDuringAnimRootMotion=false` 跳过。

### 蒙太奇"回到状态"的真实机制：Slot 权重淡出，不是状态切换

状态机全程没离开，一直在评估条件。三层：
- 逻辑层：`GetPlayLength()` 播完（`bEnableAutoBlendOut` 默认 true）
- 表现层：`BlendOut` 默认 0.25s，Slot 权重 1→0
- 位置层：同一刻 `HasAnimRootMotion()` 变 false，`Velocity` 交还 `CalcVelocity`

三层不同步 = "回位生硬"的根源。本次 clip 末段是"已转完身正在跑"，与底层 Cycle 姿势接近，看不出来。

副产品：RM 期间 `Velocity` = clip 真实移动速度 → 底层状态机的 `LocomotionState.Speed` 也是真实速度，
`Cycle` 不会误退出。但转身瞬间 clip 速度骤降 + 若 `MoveInput < 0.2` → `Cycle → Stop` 会误触发，
所以 `Cycle → Stop` 必须加 `!IsAnyMontagePlaying()`（**必需，不是保险**）。

### 由此产生的两个参数修正

- `PivotMinSpeed` 200 → **350**，新增 `PivotMaxSpeed = 650`。
  clip 按固定速度 K 制作，进入速度不匹配时 RM 第一帧就把速度硬拉到 K，肉眼可见突变。
  所以是**窗口**不是下限。Sprint(800) 被上限挡掉 → 退回纯旋转，是正确降级。
- `TurnSpeedScale` 在 `HasAnimRootMotion()` 时强制为 1（否则出蒙太奇时速度恢复被拖尾）。

## 更正：root motion 不会穿墙（用户质疑，查证后确认用户对）

### 位移：走正常物理，带扫掠，会被挡

`PhysWalking`（`CharacterMovementComponent.cpp:4456`）：
```cpp
SafeMoveUpdatedComponent(Adjusted, UpdatedComponent->GetComponentQuat(), true, Hit);  // bSweep = true
if (Hit.Time < 1.f) { HandleImpact(...); SlideAlongSurface(Adjusted, 1 - Hit.Time, Hit.Normal, Hit, true); }
```
→ **碰撞完全生效，不会穿墙**。被挡后不是停住，而是**沿墙切向滑**。

### 但旋转是无条件的

`PerformMovement` 在 `StartNewPhysics` **之后**单独应用旋转（`:3053-3060`）：
```cpp
MoveUpdatedComponent(FVector::ZeroVector, NewActorRotationQuat, true);
```
delta 为零 + **胶囊绕 Z 轴对称、旋转不改变占用空间** → 这句永远不会被墙挡住。
→ 贴墙时：转身照常完成，位移全丢 → 动画与位置脱节，滑步比不播 clip 更严重。

### 最坑：RM 期间 Velocity 不由实际位移反推

`PhysWalking` 末尾：
```cpp
if( !bJustTeleported && !HasAnimRootMotion() && !CurrentRootMotion.HasOverrideVelocity() )
    Velocity = (NewLocation - OldLocation) / deltaTime;
```
条件带 `!HasAnimRootMotion()` → 被墙挡到实际速度 0 时，`Velocity` 仍是 clip 设计速度(500)。
→ `LocomotionState.Speed` 报假值，Blend Space / `Cycle→Stop` / Lean 全错。
→ 出蒙太奇后 `CalcVelocity` 从假速度起步，角色顶着墙"跑步"。

### 结论调整

通路检查目的从「防穿墙」改为「避免白播动画」，优先级降为"先看表现再决定"。
两个方案：①触发前沿当前/新朝向各扫一次（需先量 clip 两段位移）②运行中比较实际位移/预期位移，连续 0.15s <30% 就提前 StopMontages。

## 追问：有 root motion 还需要速度包络吗？会不会互相影响

### 结论：留，但两者必须**互斥**，否则在切换那一帧互相打架

原实现漏洞：`TurnStableDwell = 0.1s` 里 `|TurnAngle|=180°` → 折扣已把速度压到 ~330；
蒙太奇开始后 clip lead-in 的 RM 速度是 500，`ConstrainAnimRootMotionVelocity` 一帧拉回 500
→ **进入瞬间速度跳 330→500**。

修法：把「要不要播」的谓词抽成 `bPivotCandidate`，复用给折扣判断：
```cpp
bPivotOwnsMotion = HasAnimRootMotion() || (bPivotCandidate && TurnStableTimer > 0);
TargetScale = bPivotOwnsMotion ? 1.0f : Lerp(1.0f, TurnBrakeMinScale, BrakeAlpha);
```
`TurnStableTimer > 0` = 输入已安静，这一帧起只是在等 dwell 走完。
好处：绕圈时输入永不安静 → `TurnStableTimer` 恒 0 → 折扣全量生效，正好是需要的方向。
一个谓词同时解决两个方向的判定。

### 更该知道的：包络对"单次 180°"根本来不及

时间账（Run=500）：
- 胶囊转完 180°：**0.17s**（`SharpTurnInterpSpeed=1080`）
- 折扣插值到接近目标：**~0.3s**（`FInterpTo`，8/s）
- 速度真被刹下去：**~0.26s**（`BrakingDecelerationWalking = 500/0.3`）

折扣还没起作用旋转就结束了。单次快转滑步只能削掉约 1/4（85cm→65cm）。这是时序问题不是参数问题；
想更快只能提高 `BrakingDecelerationWalking`，但那是全步态共用，会把正常刹车也变硬。

### 定位分工（写进文档 §5.3）

| | 管用范围 |
|---|---|
| pivot 蒙太奇 | 单次大角度反打（离散、偶发），靠 clip 自身消除滑步 |
| 速度包络 | **持续转向**（绕圈、连续调整），角度长期大 → 折扣稳定维持 |

一句话：**clip 管"那一下"，包络管"一直在转"**，时间尺度差一个数量级。
`TurnBrakeMinScale`(0.15) 是最该先调的参数：绕圈会稳定在 75cm/s，嫌慢就提到 0.3~0.4。

## 决策：OnPivotRequested 绑在角色侧，不放 AnimBP

C++ 已在 `AACTCharacterBase::PostInitializeComponents` 里 `AddDynamic`。
**蓝图子类不要再绑，否则同帧播两次蒙太奇。**

理由：
1. 与 Roll 同一条路（都在角色类 `PlayAnimMontage`），Phase 6 迁 `ActionLogicComponent` 只改一处
2. 避免第二条蒙太奇入口（动作系统需要知道所有播蒙太奇的请求）
3. AnimInstance 会重建（换装 / SetSkeletalMesh / SetAnimInstanceClass）。动态委托存的是**弱引用**
   （`TScriptDelegate::Object` = `FWeakObjectPtr`，`ScriptDelegates.h:487`），旧实例回收后
   `Broadcast` 跳过、不会崩不会阻 GC，但**死条目会留在多播列表里**累积，除非 RemoveAll
4. 线程：委托事件在广播方线程执行（Broadcast 在 CMC tick = GT），今天绑 ABP 也安全；
   但容易被"顺手"挪进 `BlueprintThreadSafeUpdateAnimation` → WT 里调 Montage_Play = UB

适合放 ABP 的情况：纯表现、不影响位移、不需被动作系统查询/打断、多角色共用 ABP 想少配资产。
pivot 接管位移和旋转，不属于这类。

顺带记一个缺口：`HandlePivotRequested` 里 `PlayAnimMontage(Montage, 1.0f)` 速率写死，Roll 有 `RollPlayRate`，
如需调速可加 `PivotPlayRate`（**未加，因为 UBT 当前不可用，新增 UPROPERTY 无法验证 UHT 生成**）。

## 构建问题定位并解决（重要，以后直接用）

## 为什么不改为状态机实现（回答用户备选方案）

`RootMotionMode` 默认 `RootMotionFromMontagesOnly`（`AnimInstance.cpp:202`）→ 状态机里的 RM 不驱动胶囊。
要吃得改成 `RootMotionFromEverything`，那**所有**状态的 RM 都会驱动胶囊，包括循环的 `Cycle` Blend Space
→ 角色会自己往前跑。不用 RM 则 pivot 的 180° 旋转和两段位移全丢，退化成"原地转身 + 硬转"。
所以状态机是更差的选择，不是退路。蒙太奇方案 + §6.7 的蓝图接口已经覆盖需求。
