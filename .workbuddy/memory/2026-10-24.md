## 梳理 ACTCharacterBase / ACTCharacterMovementComponent / ACTAnimInstance 的数据职责

- 确认三类是单向流水线：角色只产「意图」，移动组件是位移与状态的唯一权威并组装 `FActLocomotionState` 快照，动画实例只负责跨线程蒙太奇队列（故意做薄，不提供任何 Locomotion 数据）。
- 关键结论：ABP_CH_01 一律走 Property Access 读 `CharMoveComp.LocomotionState.*`，不 Cast 角色、不读曲线。C++ 侧零拷贝走 `GetLocomotionState()`（非 UFUNCTION 返回引用）。
- 发现的悬空数据：
  - `FActGaitSettings::BlendSpaceSpeed` 目前无任何消费者（ABP 未接）。
  - `LocomotionState.MoveInput` / `AccelerationMagnitude` 在 ABP 里暂无对应节点。
  - `TargetYawAngle` / `CurrentYawAngle` 未加 BlueprintReadOnly，ABP 只能读 `YawOffset`。
  - `AACTCharacterBase::GetLocomotionState()` 是 UFUNCTION 按值返回，ABP 里调用会整结构体拷贝，仅适合调试。
- 冗余但必要的设计：`FActLocomotionState.Stance` 之所以存在，是因为 CMC 的 `GetStance()` 是函数，Property Access 取不到属性路径；Gait / RotationMode 则是真重复。
- `RollMontage` / `RollPlayRate` 是唯一绕过移动系统的临时通道，Phase 6 应交给 ActionLogicComponent。

## Pivot（回转）状态：数据支持度评估 + 修 root motion 转身弹回 bug

- 结论：判定所需数据全在 `FActLocomotionState` 里，不需要新增字段。`MoveInput`（本地 X=右/Y=前）+ `VelocityYawOffset`（+右为正）相减即得输入-速度夹角。
- 夹角的蓝图算法：`InputYaw = RadiansToDegrees(Atan2(Y:MoveInput.X, X:MoveInput.Y))`，`TurnAngle = NormalizeAxis(InputYaw - VelocityYawOffset)`。Atan2 的 Y 引脚填 X、X 引脚填 Y，容易搞反。
- 坑：左右方向不能用 `TurnAngle` 的符号判定，180° 附近 NormalizeAxis 会在 ±180 翻转；要用 `MoveInput.X` 的符号。
- 改 `ACTCharacterMovementComponent`：新增 `SyncYawWithActor()`，在 `Super::TickComponent` 之后调用，把 `CurrentYawAngle`（必要时连带 `TargetYawAngle`）对齐到 Actor 实际朝向。
  - 原因：root motion 期间引擎不调 `PhysicsRotation`，朝向往动画走而两个 float 不动，蒙太奇结束后 `FixedTurn` 从旧角度插值 → 「转完弹回去再转一遍」。Pivot / 翻滚 / 处决都会踩。
  - 正常帧里差值恒为 0，不会干扰插值；`bAutoUpdateYaw == false`（攻击锁朝向）时不覆盖 TargetYaw。
- ABP 接线方案（Montage 而非 State）：Pivot 用 Montage + `Root Motion from Montages Only`，比 State + `Root Motion from Everything` 安全（后者会让所有 Locomotion 动画的 root motion 都生效）。
- **用户否决此方案，已按要求撤回 `SyncYawWithActor` 改动（.h 声明 / .cpp 实现与调用全部移除，grep 无残留）。** 最终方向：Pivot 用 **State + Distance Matching**。
  - State 路线下 root motion 不应用，朝向仍由 `PhysicsRotation` 驱动，因此不触发「转身弹回」问题，撤回无副作用。
  - 项目已有 `UEastingDistanceCurve`（替代 UE5.6 失效的 DistanceCurveModifier），可直接给 Pivot 动画烘 `Distance` 曲线。
- 发现的阻塞性 bug：`SetRotationInterpSpeed()` 用 `FMath::Max(0.0f, NewSpeed)` 钳位，与成员初值 `-1.0f`（表示"用 RotationMode 默认值"）的语义冲突。传 -1 会被钳成 0 = 冻结旋转，**导致 Pivot 结束后无法恢复默认转向速度**。应改为 `NewSpeed < 0 ? -1.0f : NewSpeed`。

## Pivot 朝向接管的线程问题（方案阶段，未写入任何代码）

- 用户指出：Pivot 判定在 `BlueprintThreadSafeUpdateAnimation`（动画工作线程），**无法调用 `SetAutoYawUpdate` / `SetTargetYawAngle` / `SetRotationInterpSpeed`** —— 这些 setter 改的是组件 UPROPERTY，且下游 `PhysicsRotation` / `MoveUpdatedComponent` 都在 GT。给它们打 `BlueprintThreadSafe` meta 只是骗过蓝图编译器，实际是数据竞争 + 生效时机不可控。
- 同一条限制也适用于 `GetACTMovement()`：头文件注释已写明 BlueprintPure 只能在 GT 调，ThreadSafeUpdate 里判定必须全部走 Property Access。
- 推荐方案：**把朝向决策从 ABP 挪回 GT**。在 `UACTCharacterMovementComponent::UpdateDesiredYaw()`（GT、每帧、PerformMovement 之前）里加 Pivot 分支，用 `GetPendingMovementInputVector()`（零帧延迟，`LocomotionState.MoveInput` 用的 `GetLastMovementInputVector()` 晚一帧）比较输入方向与速度方向，夹角超阈值就直接把 `TargetYawAngle` 对准输入方向。ABP 只需读结果决定播哪个动画，完全不碰 setter。
- 备选：`AnimNotifyState` 挂在 Pivot 序列开头（Notify 在 GT 触发）接管/恢复；或 `Event Blueprint Update Animation`（GT）里做，但会和 ThreadSafeUpdate 的判定重复。
- 附带：Pivot 期间 `YawOffset` 会瞬时接近 180°，Orientation Warping 会把腿扭歪，Warping 必须放在 Locomotion State 分支内部而不是全局应用。

## Pivot 定案方向：root motion rotation 独占旋转（结论，未实施）

- 用户提出「允许 root 骨骼偏移，让 mesh 按旋转曲线对齐胶囊体」。拆成两种实现：
  - **A（推荐）**：`bEnableRootMotionRotation=true` + `bEnableRootMotionTranslation=false` + ABP `Root Motion from Everything`。Actor 被 root motion 直接转、mesh 跟随，不存在偏移；`PhysicsRotation` 里 `HasAnimRootMotion()` 自动 return，旋转只有一个权威。
  - **B（有毒）**：`RootMotionMode=Ignore` + Transform Bone 手工转 root。mesh 转了胶囊体没转 → 两份旋转，缩放/打断/突跳问题全从这来。
- 四个衍生问题的结论：① mesh 旋转速率不需要跟 CMC 缩放（A 方案下 CMC 根本不转）；② 中途退出 Pivot 靠 TurnInPlace 可行，但会先过 Stop 状态，Stop 必须也消费 `YawOffset`（Warping 的 ±60° 上限不够）；③ 被攻击打断以**胶囊体**为准，攻击起手 `SetAutoYawUpdate(false)` + `SetTargetYawAngle(目标, bInstant=true)`；④ A 方案下打断时 mesh 与 Actor 严格一致，不会突跳。
- **用户最后问「是否要裁掉回转点之前的动画数据」。结论：不该裁。** 全量 root motion 时 `CalcVelocity` 被跳过、`Velocity` 由 root delta 反算，裁掉前冲段会让第一帧位移≈0 → 速度从 MaxSpeed 瞬间掉到 0，表现为撞墙式急停。前冲段是「把 MaxSpeed 消化掉」的唯一载体。保留下来的话退出 Pivot 时 `Velocity` 已是反向跑速，无缝接回 Locomotion。
- root motion 与 Distance Matching **必须二选一**：全量 root motion 下 Distance Matching 靠位移推时间、root delta 又按时间取，形成循环依赖。
- 速度匹配用 `PlayRate = 实际速度 / 动画假设初速`（root motion 位移与时间等比缩放），或按 Walk/Run/Sprint 分档出动画。

## AnimNotify 运行时不触发的定位（Pivot）

- `EnableYawUpdate` 是蓝图 AnimNotify：`Content/Blueprints/AnimNotifies/EnableYawUpdate.uasset`，类名无 `AnimNotify_` 前缀，所以 ABP Event Graph 里的节点名是 `AnimNotify_EnableYawUpdate`（搜 `AnimNotify` 或全名）。
- **根因：Pivot 状态里用的是 `Sequence Evaluator`，该节点默认 `bCanProcessNotifies = false`，不处理 AnimNotify。** Sequence Player 默认是开的，换成 Evaluator 后行为静默改变。编辑器里双击序列预览走的是正常时间轴，所以会触发，造成误判。
- Sequence Evaluator 的时间是「按帧跳变」而非累积推进，即使打开 Notify，跨帧跳过的通知也会被丢掉。Distance Matching 与 root motion 都只配 Sequence Player。
- 结论：Pivot 应回到 `Sequence Player`（支持 Notify / Distance Matching / root motion / `Get Relevant Anim Time Remaining` 判定退出）；Sequence Evaluator 留给处决、命中对齐这类需要钉帧的场合。若此前用 Evaluator 是为了 Lfoot/Rfoot 两套动画的相位同步，Sequence Player 同样支持 Sync Group，换过去不丢功能。
