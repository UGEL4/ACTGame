### 三个线程阶段
- `NativeInitializeAnimation`（GT）：缓存 `Character` / `ACTMovement`，找不到组件时退化为基础速度数据
- `NativeUpdateAnimation`（GT）：`LocomotionState = ACTMovement->GetLocomotionState()` 拷快照 + flush 蒙太奇队列
- `NativeThreadSafeUpdateAnimation`（WT）：算全部混合权重，只写 WT-only 成员

### 核心设计：AnimSpeed + StrideScale 替代 Distance Matching
- `AnimSpeed` = Speed 的滞后版（FInterpTo 8/s）→ Blend Space 轴
- `StrideScale` = Speed / AnimSpeed → Stride Warping
- 起步 AnimSpeed<Speed → StrideScale>1 放大步幅；急停 AnimSpeed>Speed → StrideScale<1 缩步幅锁脚
- 不需要 root motion

### 引擎源码核对结论（重要）
- `AnimNode_StrideWarping.cpp:203-210`：只有 Graph 模式才用 `LocomotionSpeed / CachedRootMotionDeltaSpeed`
  自动算；Manual 模式的 `LocomotionSpeed` 引脚**被忽略**，只用 `StrideScale` 倍率
- `AnimNode_OrientationWarping.cpp:377`：Manual 模式 `OrientationAngle` 直接就是绕 Z 的旋转角度
- `FAnimNode_FootPlacement::PlantSpeedMode` 默认 Manual，需 `SpeedCurveName` 脚速曲线；
  切 Graph 需 root motion delta。**in-place 无曲线时节点静默不工作** → v1 不加，推迟 Phase 5

### 决策：Blend Space 用 1D（仅 Speed 轴），不加 Direction 轴
Direction 在转身过程中会冲高（0→90°）再回落，2D BS 会跟着播一遍"右移动画"，
和 Orientation Warping 叠加成双重转向。正确分工：BS 只管"多快"，Orientation Warping 管"朝哪"。
一套前进动画即可覆盖全方向移动。

### 输出字段（11 个）

`OrientationAngle`、`StrideScale`、`AccelerationLean`、`TurnLean`、`LandPredictionAlpha`

### 蒙太奇

GT 的 `NativeUpdateAnimation` 里 flush；先处理停止请求再处理播放请求。

## 引擎已有停止距离预测 → 删掉自己写的 v²/2a

- `UAnimCharacterMovementLibrary`（插件 `AnimationLocomotionLibrary`，模块 `AnimationLocomotionLibraryRuntime`）：
  - `PredictGroundMovementStopLocation(Velocity, bUseSeparateBrakingFriction, BrakingFriction, GroundFriction, BrakingFrictionFactor, BrakingDecelerationWalking)`
  - `PredictGroundMovementPivotLocation(Acceleration, Velocity, GroundFriction)`
  - 两者都是 `BlueprintThreadSafe`，实现见 `AnimCharacterMovementLibrary.cpp:7-56`
- 停止公式：`T = Speed / (摩擦×Speed + BrakingDecel)`，`摩擦 = (bUseSeparate ? BrakingFriction : GroundFriction) × BrakingFrictionFactor`，
  停止点 = `V×T + 0.5×(-摩擦×V - BrakingDecel×Dir)×T²`。
- 本组件 `BrakingFrictionFactor = 0` → 摩擦项归零 → 化简正好是 `v²/2a`，**两者当前数值完全一致**。
- `UACTAnimInstance` 改为调用引擎函数（`StopLocationOffset` + `BrakingDistance = Size()`），
  避免以后调摩擦时出现第二套算法；`Build.cs` 加了 `AnimationLocomotionLibraryRuntime` 依赖。
- `PredictGroundMovementPivotLocation` 留给 Phase 5 的 Turn 状态；注意它要 Acceleration，不能现算。

## 状态机转移条件：EACTGait 不能做 Idle→Start 的触发条件

- `Gait` 只由输入设置（`ACTCharacterBase.cpp:207-220`），完全不看速度 → 是**输入意图**不是**运动状态**。
  反例：站着按住 Shift 时 Gait=Sprint；Idle 推摇杆全程 Gait 一个值都不变（**没有边沿**，进不去 Start）；
  跑动中升档会误判"起步"。
- **Idle→Start 用 `Speed > 15`**：`AdvanceTimeByDistanceMatching` 靠累计位移推进 clip，
  速度 0 时位移不增长 → clip 冻在第 0 帧。用速度做条件天然自洽。
- **Cycle→Stop 必须带 `MoveInput.Size() < 0.2`**：只看 `BrakeAmount` 会在 Run→Walk 降档
  （`SmoothedMaxSpeed` 0.2s 插值，500→150）时误触发停止动画，而玩家还按着前进键。
- `Gait` 的正确定位：**进入状态那一刻锁存**，用来选播哪段 clip。用 State Result 节点的
  **On State Entry / On State Exit** 函数（`AnimGraphNode_StateResult.h:49-71`，
  `Prototype_ThreadSafeAnimUpdateCall`，线程安全）。每帧读 Gait 切 clip 会让已累计的
  `DistanceTraveled` 对应到另一条 `Distance` 曲线 → 姿势跳变。
- Gait→clip **不能枚举对枚举**：`EACTGait` 三值，`PC_01_*` 只有 Walk/Jog 两套起停。
  Sprint 候选 `A_PC_01_Sprint_Acceleration` / `A_PC_01_Stop_Left/Right`（需打开确认是否为过渡段）。
- 状态机加了独立 `Idle` 状态（原拓扑只有 Grounded/Start/Stop/Jump/Fall/Land）。

## 更正：Idle 必须放进 BS（推翻昨天的结论）

昨天写的"Idle 不要放进 BS"是错的。`Stop` 是独立状态、不经过 BS；而 `Cycle` 里速度仍可能掉到 0
（顶墙、被击退、胶囊体卡住），BS 最左采样点必须是一个合理的静态姿势 = Idle。
且 `Stop` 末帧姿势就是 Idle，0 点放 Idle 才能让 `Stop → Idle` 无跳变。

## 线程归属：DistanceTraveled / LatchedGait 要放 BlueprintThreadSafeUpdateAnimation

放 `Blueprint Update Animation`（GT）而 State Machine 在 WT 读 → 数据竞争，不报错但表现为偶发进度跳变。
`AnimInstance.h:580` 的 `BlueprintThreadSafeUpdateAnimation(DeltaTime)` 自带 DeltaTime 入参。
另外 `DistanceTraveled` 必须在 **State Exit** 清零，不能靠速度阈值判。
