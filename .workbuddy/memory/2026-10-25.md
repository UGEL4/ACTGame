# 2026-10-25

## ABP 事件图表搜不到 AnimNotify_XXX 的根因（已查证引擎源码 UE5.8）

结论：**蓝图 AnimNotify 子类永远不会在 ABP 事件图表里生成 `AnimNotify_XXX` 节点**，与类名前缀无关。

1. 菜单来源只有两处，都排除蓝图通知：
   - `AnimSequenceBase.cpp:833-843` `GetAssetRegistryTags()`：`if (Iter->IsBlueprintNotify() == false)` 才把 `NotifyName` 写进 `USkeleton::AnimNotifyTag`，注释写 "handled separately"。
   - `UAnimBlueprintGeneratedClass::AnimNotifies` 全引擎只有 `PurgeClass()` 里的 `Empty()`，没有任何 `Add` → `GetInstanceActions()` 恒为空。
   - `UAnimNotifyEventNodeSpawner::Create()` 事件名确实是 `AnimNotify_%s`，但上面两条路对 BP 通知都不产出。
2. 运行时派发也不可达（`AnimInstance.cpp:2060+ TriggerSingleAnimNotify`）：
   ```cpp
   if (AnimNotifyEvent->Notify != nullptr)  { Notify->Notify(...); }   // 蓝图通知走这里 → Received_Notify
   else if (NotifyName != NAME_None)        { FindFunction(AnimNotify_XXX)->ProcessEvent; }
   ```
   蓝图通知 `Notify != nullptr`，第二支永远进不去。
3. `UAnimNotify::Notify()` 实现就是 `Received_Notify(MeshComp, Animation, EventReference)`。
4. NotifyState 一直是对象调用（`NotifyStateClass->NotifyBegin/Tick/End`），所以它的 BP 逻辑能用。

正确用法：逻辑写在 `EnableYawUpdate` 自己的 `Received Notify` 里，`MeshComp → Get Owner → GetComponentByClass(ACTCharacterMovementComponent)` 调 `SetAutoYawUpdate` / `SetTargetYawAngle` / `SetRotationInterpSpeed`（三者均 BlueprintCallable，.h:66/74/85），Notify 在游戏线程执行。

附注：若最终采用 root motion rotation 方案，这个通知多余 —— `PhysicsRotation()` 里 `HasAnimRootMotion()` 会自动 return，结束后自动恢复。
