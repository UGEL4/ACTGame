## ALS-Refactored 插件 C++ 源码分析

- 通读 `Plugins/ALS-Refactored/Source` 全部 4 个模块（ALS / ALSCamera / ALSEditor / ELSExtras，约 1.8 万行），产出学习笔记 `Docs/ALS-Refactored-Code-Study.md`。
- 插件版本：ALS-Refactored 4.18，`EngineVersion: 5.8`（项目本身也是 5.8，与旧记忆中的 5.6 不符，已更新）。
- 核心结论：三层严格分离（角色层唯一旋转权威 / 移动层 FSavedMove 装载预测参数 / 动画层 GT-WT 两段式）。
- 项目现状确认：
  - `AACTCharacterBase : public AAlsCharacter`（ACTCharacterBase.h:23）
  - `UACTGameAnimInstance : public UAlsAnimationInstance`（ACTGameAnimInstance.h:19）
  - `UACTCharacterMovementComponent : public UCharacterMovementComponent`（**不是** UAlsCharacterMovementComponent），且全项目无引用，属死代码。
- 风险点：若把该组件设为 CharacterMovement 类，`AAlsCharacter::PostInitializeComponents`（AlsCharacter.cpp:49 / 126 / 130）会在无空检查的情况下解引用 `AlsCharacterMovement`，导致空指针崩溃。
- 待决策：ACT 战斗动作状态是否扩展 ALS 的单值 `LocomotionAction`，还是交给 GAS 的 ActivationOwnedTags 管理（倾向后者，ALS 只保留移动层接管语义）。

## 自研 Locomotion 重构方案（脱离 ALS）

用户明确要求：自研 Character / MovementComponent / AnimInstance，用 UE 5.8 高级动画节点重建 ABP，
**不用 Motion Matching**（资源不足）、**暂不做网络同步**。

### 资产现状（重要基线）
- 动画资源分布在 **4 套骨架**：`UE4_Mannequin_Skeleton`（MartialArtsFightGame 196 个 + InsaneAirCombo 141 个 + Mannequins 90 个）、`Pl0001_Skeleton`、`reverse_grip_Skeleton`、`UEFN_Mannequin_Skeleton`。
- **无统一参考姿势、无内置曲线** → ALS 的 `Apply Additive` / `LayeredBlendPerBone` 姿态叠加路线结构性失效；曲线驱动路线（`RotationYawOffsetCurve` 等）也失效。
- 已启用插件：`AnimationWarping`、`AnimationLocomotionLibrary`（正好替代 ALS 的曲线方案）。
- `Build.cs` 已依赖 `AnimationModifiers` / `AnimationModifierLibrary` / `AnimationBlueprintLibrary` → 可写 `UAnimationModifier` 批量烘 `Distance` 曲线（若 clip 有 root motion）。

### 架构决策
- **依赖倒置的起手顺序**：资产体检 → 数据契约 → 移动组件 → 角色类 → ABP v1（**不要从 ABP 开始**）。
- 数据契约 `FActLocomotionState`：14 个字段以内，全部是已算好的标量，动画层只读、不 cast、不读曲线。
- 砍掉 ALS 三块复杂度（因不做网络同步）：`FAnimInstanceProxy` 的 PostUpdate 补丁、`FSavedMove` 预测参数、`Desired*`/实际值双状态。
- 硬件约束：`Orientation Warping` / `Stride Warping` / `Foot Placement` **都依赖 IK Rig 资产**，须先为骨架建 IK Rig。
- AnimGraph 顺序（自下而上求值，靠 Root 的最后执行）：`State Machine → Orientation Warping → Stride Warping → Slot → Foot Placement → (Control Rig) → Root`。Foot Placement 必须最靠 Root 才能修正蒙太奇姿势。
- 起步/停止/回转不自然 = 位移未对齐，lean 只是美术表现。四件套：Stride Warping（步幅）/ Orientation Warping（转身）/ Offset Root Bone（残余位移）/ 专用 start-stop clip（时长对齐，不可省）。
