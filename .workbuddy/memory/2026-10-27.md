
## pivot 判定重做：参照系从「角色朝向」换成「速度」（用户提议点乘，查证后取其精华）

### 用户问题
`AbsOffset = |TargetYawAngle - ActorYaw|` 计算结果异常（一直不变 / 一直是 0）。
用户提议用 `Dot(Velocity, Acceleration) < 0` 判反向，再卡角度 135。

### 根因（数学可证，pivot 根本不可能触发）
1. `TargetYaw - ActorYaw` 是**剩余角**，身体在 `SharpTurnInterpSpeed=1080` 下 **0.17s** 转完，
   而且是**斜坡**（180→90→0）。
2. 原判据要求 `SmoothedTurnRate < TurnStableRate(120)` 持续 0.1s。
   反打首帧原始角速度 ≈ 11000 deg/s，`FInterpTo(rate=12)` 衰减到 120 需 **0.24s**，
   加 dwell 共 0.34s > 0.17s → 条件满足时角度已归零。**两个条件时间上互斥。**

### 结论：用 `angle(InputYaw, VelocityYaw)`，不用点乘
- `Dot(V,A) < 0` ⟺ `angle(V,A) > 90°`，只是角度判据的**弱化版**；`A` 的方向就是输入方向
  （`Acceleration = ScaleInputAcceleration(ConstrainInputAcceleration(InputVector))`,
  `CharacterMovementComponent.cpp:6451`；`ScaleInputAcceleration` 只乘 MaxAcceleration 不改方向），
  所以点乘能给的只有符号，丢掉 90~140 的区分。要 140° 门槛本来就得算角度 → 点乘冗余。
- 另外三条取用问题：`Acceleration` 是 protected（Property Access 读不到）；
  在 `ControlledCharacterMove` 里赋值，而它在 `Super::TickComponent` 内执行，
  我们的 `UpdateTurnState` 在 Super 之前 → 读到上一帧值；`bFailMove` 时被清零（`:5483`）。
- **真正的价值**：参照系换成速度。速度反向要 `TimeToStop(0.3)+TimeToMaxSpeed(0.35)`，
  且中途是**阶跃**（前 0.3s 一直 180°，过零后突然变 0）。所以整个反向窗口读到的都是稳定 180。
  → **不再需要锁存、不需要 0.35s 有效期、不需要"角速度衰减"判据。**

### 现行实现（`ACTCharacterMovementComponent`）
```
ResidualAngle = TargetYaw - ActorYaw        // 斜坡 → 只给速度包络 / LocomotionState.YawOffset
TurnAngle     = InputYaw  - VelocityYaw     // 阶跃 → 给 pivot 判定
bPivotPending = bAutoUpdateYaw && RotationMode==VelocityDirection && bInputDrivenThisFrame
             && |TurnAngle| > PivotAngleThreshold(140)
             && Speed in [350,650] && Cooldown 已过 && IsMovingOnGround()
fire: bPivotPending && TurnStableTimer >= TurnStableDwell(0.05)
      → PivotCooldownTimer, PivotFreezeTimer=0.08, Broadcast(TargetYaw - ActorYaw)
```
- 绕圈只靠 `TurnInputSettleAngle`(25°/帧) 排除：绕圈上限 ~1800deg/s = 30°/帧，永远过不了。
- `bPivotRotationFrozen = bPivotPending || PivotFreezeTimer>0` → `PhysicsRotation` 直接 return，
  否则确认那几帧会吃掉 30~90°，clip 从 0 转 180 就转过头。
- 新增成员：`InputYaw` / `bInputDrivenThisFrame` / `PivotFreezeTimer`；
  删除：`TurnRequestMinAngle` / `TurnRequestCancelAngle` / `TurnRequestHoldTime` /
  `RequestedTurnAngle` / `TurnRequestTimer` / `TurnStableRate`。
- `PrevInputYaw` 现在只在输入驱动时更新（原来松手滑行会被速度方向污染，重新推摇杆会造假跳变）。

## 新增备选路径：状态机 pivot + 曲线驱动旋转（用户提议）

### 关键前提纠正：`RotationRate` 在本项目是死参数
`bOrientRotationToMovement=false` / `bUseControllerDesiredRotation=false` / `RotationRate=Zero`（构造函数 :34-36）；
基类 `PhysicsRotation` 第一行 `if (!(bOrient||bUseCtrlDesired)) return;`（`CharacterMovementComponent.cpp:6632`），
`RotationRate` 只喂 `GetDeltaRotation`。我们的 override 也不读它。→ 蓝图改 RotationRate 毫无效果。
ABP 里 `SetActorRotation` 同样不行：绕过 `CurrentYawAngle` 缓存 → 下帧 FixedTurn 拽回（"转过去又弹回"）。

### 新增 API（`ACTCharacterMovementComponent`）
- `SetAnimationDrivenYawOffset(float YawOffsetDeg)`：**偏移量语义**，进入时 CMC 记 `AnimDrivenEntryYaw`，
  内部 `AnimationDrivenYaw = EntryYaw + Offset`。为什么不是绝对角：曲线首帧是 0，绝对语义会跳到 yaw=0。
- `ClearAnimationDrivenYaw()`：退出时必须调，否则 PhysicsRotation 永久停在曲线分支。
- `IsAnimationDrivenYaw()`。
- `PhysicsRotation` 里 `bAnimYawDriven` 分支**不插值**，直接落位（曲线已含慢-快-慢）。
- `bPivotPending` 加 `!bAnimYawDriven`；`bPivotOwnsMotion` **不含** `bAnimYawDriven`
  （状态机只接管旋转，位移还在，更需要减速防滑）。

### 曲线：用 `UMotionExtractorModifier`（AnimationModifierLibrary，已在 Build.cs）
`MotionType=Rotation`（**不是 RotationSpeed**）+ `Axis=Z` + `LocalSpace` + `bRelativeToFirstFrame=true`
→ 曲线 `root_rotation_Z`，有符号累计偏航角（度）。
`RotationSpeed` 被强制取正（`MotionExtractorUtilities.cpp:170-186`），左右方向丢失，不能用。
曲线名格式 `<Bone>_<motiontype>_<Axis>`（`:88`）。

### 已知新坑
`Orientation Warping`（Graph，LocomotionDirection←VelocityDirection）会和曲线驱动旋转对冲，
pivot 状态里必须关掉（或权重给 0）；`Foot Placement` 保留。
位移三条路：A 只播原地转身段（推荐）/ B 烘焙 Distance 曲线自驱（等于手写 RM）/ C FromEverything（不可行，Cycle 会自己跑）。

## 补：动画驱动朝向改为 WT 安全（原子槽 + GT 消费）

用户要求能在 `BlueprintThreadSafeUpdateAnimation` 里调 → 原来直接在函数里读 `CharacterOwner->GetActorRotation()`
并写 UPROPERTY 是数据竞争，必须拆开。

### 引擎依据（可被 WT 调用的条件）
`AnimGraphNode_CallFunction.cpp:249-259`：
- 不能是 `BlueprintPure`（`PureFunctionError`）
- 必须有 `BlueprintThreadSafe` 元数据（否则 `ThreadSafetyError`）
- `AreFunctionParamsValid`：**不允许返回参数**（Return parameters are not allowed）
→ 所以签名必须是 `UFUNCTION(BlueprintCallable, meta=(BlueprintThreadSafe)) void Fn(float)`。

### 实施
WT 侧（`SetAnimationDrivenYawOffset` / `StopAnimationDrivenYaw`）**只写三行原子**：
`AnimYawOffsetSlot`(atomic<float>) / `AnimYawActiveSlot`(atomic<bool>) / `AnimYawSeq`(atomic<uint32> fetch_add)。
不读 CharacterOwner、不读 ActorRotation、不写 UPROPERTY、不打日志（这些都会变成竞争）。

GT 侧 `ConsumeAnimationDrivenYaw(DeltaTime)` 在 `TickComponent` **最前面**调用：
- 未激活 → `EndAnimationDrivenYaw()`
- 序列号 0.25s 不变（`AnimYawTimeout`）→ 看门狗收尾 + Warning（防漏调 Stop 导致永久卡在曲线分支）
- 首次收到 → 在 GT 读 `GetActorRotation().Yaw` 记 `AnimDrivenEntryYaw`，并同步 `CurrentYawAngle`
- 之后 `AnimationDrivenYaw = NormalizeAxis(EntryYaw + Slot)`

### 代价与取舍
- **晚一帧**：动画 WT 在网格 Tick 内，晚于 CMC Tick。60fps 16ms；pivot 曲线角速度 360~720deg/s
  → 6~12° 滞后。要消除必须把旋转施加挪到动画之后（等于动画驱动物理），不做。
- 基准角只能在 GT 取（胶囊 transform 在 GT 上随时可能被移动）。
- 曲线首帧必须为 0，靠 modifier 的 `bRelativeToFirstFrame` 保证，否则进状态瞬间会跳。

### 构建
UHT 正常（gen.cpp 有 11 处 StopAnimationDrivenYaw）；两个 TU 手动 cl exit 0；
手动 link exit 0，DLL 1.92MB @ 17:55。UBT 本身仍因 UBA memgroups 权限失败。

## 修正：SetAnimationDrivenYawOffset 移到 UACTAnimInstance（用户报"没有线程安全的 self"）

### 原因
`BlueprintThreadSafeUpdateAnimation` 里只有 self。要走到移动组件必须
`TryGetPawnOwner → Cast<ACharacter> → GetCharacterMovement()`，而
**`ACharacter::GetCharacterMovement` 没有 BlueprintThreadSafe 标记** → 整条链在 WT 上编译不过。

编译器校验实现：`KismetCompilerMisc.cpp:1884 CheckFunctionThreadSafety`，
它维护一个 `ThreadSafeObjectTerms` 集合，只放行「thread-safe 函数的返回值 / 入参对象引用」
经 Cast 传播下来的对象。CMC 引用不在集合里 → 报错。

另：`AnimGraphNode_CallFunction.cpp:249-259` 要求「非纯 + BlueprintThreadSafe + 无返回参数」，
所以签名必须是 `BlueprintCallable + meta=(BlueprintThreadSafe) void Fn(float)`。

### 现在的分层
- `UACTAnimInstance::SetAnimationDrivenYawOffset(float)` / `StopAnimationDrivenYaw()`
  —— BlueprintThreadSafe、目标 = self、只写自己的三个原子槽。**WT 侧零跨对象调用**。
- `UACTAnimInstance::IsAnimYawDriveActive()/GetAnimYawDriveOffset()/GetAnimYawDriveSeq()`
  —— 普通 C++ 内联，只给 CMC 在 GT 上拉。
- `UACTCharacterMovementComponent::ConsumeAnimationDrivenYaw()` 在 TickComponent 最前面，
  `Cast<UACTAnimInstance>(GetMesh()->GetAnimInstance())` 拉槽位；CMC 侧不再有 atomic 成员。
- CMC 依赖 Animation/ACTAnimInstance.h（同模块，单向）。

### 构建
`Result: Succeeded`（UBA 这次自己恢复了），DLL 1.92MB + `.lib` 259KB @ 18:15，
UHT 已把 16 处反射从 CMC 移到 AnimInstance。
