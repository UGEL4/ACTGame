## 旋转权威双模式（MovementComponent / AnimationCurve）

**背景**：上一轮承认手写 `PhysicsRotation` 是复杂化了（引擎 `ComputeOrientToMovementRotation`
用的就是 `Acceleration`=输入方向，不是我注释里说的 `Velocity`）。但 pivot 需要曲线控节奏，
引擎恒角速度做不到，所以做成可切换的两条路，而不是单纯回退。

**新增**：
- `EACTRotationAuthority`（LocomotionTypes.h）：`MovementComponent` / `AnimationCurve`
- CMC：`SetRotationAuthority` / `GetRotationAuthority` / `BeginAnimationDrivenYaw` /
  `EndAnimationDrivenYaw` / `SnapYawTo` / `ApplyRotationSettingsToEngine` /
  `ApplyAnimationDrivenYaw` / `ResolveAnimInstance`，`AnimationYawTimeout=0.5s`
- AnimInstance：`PushYawCurveOffset` / `ClearYawCurveOffset`（BlueprintThreadSafe）+
  `ReadYawCurve` / `ResetYawCurve` / `GetYawCurveSeq`（GT 侧），atomic {Offset, Seq, Active}

**关键设计**：
- `MovementComponent` 模式直接 `Super::PhysicsRotation()`，`bOrientRotationToMovement` +
  `RotationRate.Yaw` 由 `ApplyRotationSettingsToEngine` 独占写入
- `AnimationCurve` 模式**不限速**，曲线每帧值直接 `MoveUpdatedComponent` 落位
- 必须有序号（Seq）而不只是 bool：`PhysicsRotation` 与动画更新不同线程不同频，
  且 `PerformMovement` 可能子步调用两次
- 内存序：Push 先写 Offset 再 release 递增 Seq；Read 先 acquire 读 Seq 再读 Offset
- **超时兜底是重点**：上一轮删的那套通道就是死在"没人兜底"，ABP 忘了 Clear 会永久卡住
- 曲线模式下外部传送会把 `AnimDrivenEntryYaw` 一起搬（1° 阈值），否则会被曲线拉回原位

**删除**：`PhysicsRotation` 手写实现(51行)、`UpdateDesiredYaw`(39行)、`TargetYawAngle`/
`CurrentYawAngle`/`bInstantYaw`、`SetTargetYawAngle`/`GetTargetYawAngle`、
`SetRotationInterpSpeed`/`GetRotationInterpSpeed`/`RotationInterpSpeedOverride`、`MinSpeedToOrient`。
行数 678 → 835（涨了，但朝向状态机没了）。

**行为变化**：松手滑行不再转头（引擎 Acceleration=0 时保持朝向）；`SetAutoYawUpdate(false)`
语义变窄为"引擎完全不转"（旧版是"目标角不刷新但仍朝旧目标转"），BP_PC_01 那处调用需复查。

### 修正：引擎默认实现做不到"点按松手续转"

**用户实测反馈**：切到引擎 `bOrientRotationToMovement` 后，点按方向键的手感变差，之前手写版更好。

**根因**（源码确认）：`ComputeOrientToMovementRotation` 在 `Acceleration.SizeSquared() <
KINDA_SMALL_NUMBER` 时 `return CurrentRotation`。`RequestedVelocity` 那条分支只服务 AI 的
`RequestDirectMove`，玩家输入不走。所以松手 = 立刻放弃旋转。
每帧最大转角 `RotationRate.Yaw * dt` = 540 × 0.0167 ≈ 9°，点按 1~2 帧只能转 9~18°。
旧实现松手后用 `Velocity` 方向续转（惯性还在就转完），这是手感的关键。

**修法**：`PhysicsRotation` 的 MovementComponent 分支不再调 `Super`，自己选目标：
顺序「相机 → 输入(Acceleration) → 速度(Velocity, > MinSpeedToOrient) → 寻路请求(bHasRequestedVelocity)
→ 保持」，速度仍用 `RotationRate.Yaw`（唯一入口），`FMath::FixedTurn` + `MoveUpdatedComponent`。

**关键**：这个顺序必须和 `UpdateLocomotionState` 里算 `LocomotionState.YawOffset` 的顺序**完全一致**，
否则动画会去补一个物理已经在补的差（Orientation Warping 双重修正）。

**代价**：两个引擎 bool 恒 false，放弃 `HasCustomGravity` / `ShouldRemainVertical` /
`bPreventNonVerticalOrientationBlock`。本项目角色恒竖直、无自定义重力，用不上。

`ApplyRotationSettingsToEngine` → 改名 `RefreshRotationRate`（只按 RotationMode 刷 RotationRate.Yaw）。
`SetAutoYawUpdate` 不再刷速率（PhysicsRotation 每帧自己看 bool）。
`MinSpeedToOrient`（默认 5 cm/s）加回来了。

**编译**：Result: Succeeded（仅 CombatStateTreeUtility.h 的 C4996 无关警告）。
**文档**：附录 D.8，同时修正了 D.1 表格与 D.4 第 1 条（那条原先误判为"修正"，是错的）。

### 再修正：目标角必须是持久状态（点按手感）

**实测反馈**：D.8 的修法仍不达标 —— 点按 A 转不到 90°，点按 S 转不到 180°。

**数值推演**：MaxAcceleration=1429，按 1 帧速度 23.8 cm/s；BrakingDecel=1667 →
**14ms（0.9 帧）就归零**。每帧最大转角 540×0.0167=9°。所以点按总共只有约 18°。
**靠 Velocity 兜底根本没时间转**，速度比转身快一个数量级。

**真根因**：D.8 把目标做成了**无状态**（每帧从输入/速度现算）。改造前那版有
`UPROPERTY(Transient) float TargetYawAngle` 持久状态：按一下 A 目标就是 90°，松手后
输入没了、速度也没了，**但目标留着**，PhysicsRotation 继续朝它转直到对准。

**最终实现**（恢复旧版结构 + 保留 RotationRate 作为速度）：
- `TargetYawAngle` 恢复为持久状态
- `UpdateDesiredYaw()` 在 `Super::TickComponent` 之前调，顺序：相机 → 输入 → 寻路请求 → 速度 → **保持**
- `PhysicsRotation` 只做 `FixedTurn(CurrentYaw, TargetYawAngle, RotationRate.Yaw * dt)`
- 速度仍是 `RotationRate.Yaw`，没有第二套配置

**四个必须同步 TargetYawAngle 的地方**（漏一个就会"转过去又被转回来"）：
`BeginPlay`（=当前朝向，否则第一帧冲向世界 0°）、`SnapYawTo`（=新朝向，否则折返变抖动）、
`BeginAnimationDrivenYaw`、`EndAnimationDrivenYaw`（都对齐到进入/退出时的实际朝向）。

**曲线模式共存**：`PhysicsRotation` 只按 `RotationAuthority` 分叉；`UpdateDesiredYaw` 在曲线
模式下仍跑（不参与旋转），保证切回时目标角已是最新；`LocomotionState.YawOffset` 直接取
`AnimDrivenYaw` 或 `TargetYawAngle`，天然同源。

**编译**：Result: Succeeded。文档 D.9；D.8 已标注"修法不完整"。

**教训**：把持久状态改成"每帧现算"看起来更简洁，但会丢掉"意图的延续性"。
输入是瞬时的，朝向是持续的 —— 中间必须有一个记住"我说过要转去哪"的变量。
