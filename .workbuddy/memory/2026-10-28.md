## 旋转 / 急停 / pivot 曲线驱动重构方案（Docs/Turn-Pivot-CurveDriven-Design.md）

**产出**：新增设计文档 `Docs/Turn-Pivot-CurveDriven-Design.md`，取代 `Turn-180-Design.md` 的 §6/§7 实现路线
（v1 的"蒙太奇 root motion + 旋转提速"被判为应淘汰，§3.2「速度参照判定」的结论保留）。

**核心结论**：把旋转从"物理按角速度追目标角"改成"动画按曲线推增量"。

1. `EACTRotationAuthority { Locomotion, Animation }` 取代并存四路让路分支
   （`HasAnimRootMotion` / `bAnimYawDriven` / `bPivotRotationFrozen` / `bInstantYaw`，CMC.cpp:137/157/165/172）。
2. pivot 从蒙太奇降级为状态机状态 → 不占 DefaultSlot、无 `bStopAllMontages`、
   `Speed` 不再是 RM 假速度、可被攻击状态机按优先级打断。
3. 曲线契约 3 条：`Pivot_Yaw`（角度+节奏，MotionExtractor Rotation/Z）、
   `Pivot_Window`（旋转时机门，手 K）、`Pivot_Speed`（速度包络，TranslationSpeed/参考速度）。
   角度用 `k = 需求角 / clip 角`（clamp 0.55~1.45）缩放，一套 180° 资产覆盖 140~180°。

**新发现的关键 bug 级问题（此前文档未记录）**：
- 包络只是"上限"不是"减速"：引擎超速时仍走 `BrakingDecelerationWalking`（CharacterMovementComponent.cpp:3907-3915），
  Run=500 下 `Pivot_Speed` 若 0.1s 内 1.0→0.15，需要 4250 cm/s² 而基础只有 1666 → 冲出去约 1.2m。
  修法：CMC 里用 `SmoothedMaxSpeed * |ΔAnimSpeedScale|/Δt` 动态抬 `BrakingDecelerationWalking`。
- `PredictGroundMovementStopLocation` 只按 `BrakingDecelerationWalking` 推，与实际 over-max/加速分支不一致（S3），
  改由 CMC 输出 `LocomotionState.PredictedStopDistance` 作为唯一权威。

**三个类职责调整**：
- `AACTCharacterBase`：删 pivot 蒙太奇 139 行（`HandlePivotRequested`/`PlayPivotFromSection`/`StopPivotMontage` 等），
  只加 `MoveIntentYaw`（`Input_OnMove` 里直接算，消除 `GetLastMovementInputVector` 的一帧滞后）。
- `UACTCharacterMovementComponent`：只留判定 + 落位；新增 `BeginPivotWindow`/`EndPivotWindow`（幂等）/`PushAnimSpeedScale`；
  删 `TurnSpeedScale`、`bPivotRotationFrozen`、`SharpTurnInterpSpeed` 等。
- `UACTAnimInstance`：3 个原子槽合并为 `PushPivotDriver(Offset, Window, Speed)`，只做通道不解释语义。

**引擎事实核对（5.8）**：`UAnimDistanceMatchingLibrary`（AdvanceTimeByDistanceMatching / DistanceMatchToTarget）、
`PredictGroundMovementPivotLocation` 都在 `AnimationLocomotionLibrary`，带 BlueprintThreadSafe，可当 Anim Node Function；
`UAnimInstance::GetCurveValue` 走 `GetProxyOnGameThread` → **只能在 GT 读**（不能放 `BlueprintThreadSafeUpdateAnimation`），
滞后 1 帧；`UMotionExtractorModifier` 支持 `bUseCustomCurveName` + `MathOperation/Modifier`。

**待办**：步骤 0~9 未执行，代码未改。下一步应先烘 `Pivot_Yaw`/`Pivot_Speed` 曲线验证资产，再动 CMC。

## 死代码清理（三类的无用代码与数据）

**方法**：uasset 的 FName 名表是明文，用 `grep -ra "<Symbol>" Content` 当引用图。
关键不对称：**缺名能证明"没用"，有名不能证明"在用"**（删节点后名字会残留）。对照组 `CameraBoom` 验证有效。
在用且不能删：`HandlePivotRequested`(BP_PC_01 重写)、`StopPivotMontage`、`SetAutoYawUpdate`(ABP+BP)、
`StopAnimationDrivenYaw`(ABP)、`GetACTMovement`(40 处)、`LocomotionState`(29 处)。

**删除（净 -265 行，2173 → 1908）**：
- 角色：`PlayMontageFromTime` / `PlayPivotFromSection` / `GetPivotMontagePosition`
- CMC：`GetCurrentYawAngle` / `GetTargetYawAngle` / `IsSharpTurning` / `GetTurnSpeedScale` / `IsLanding` /
  `IsAnimationDrivenYaw` / `SmoothedTurnRate`(纯写不读的诊断量) + `TurnRateSmoothingRate`
- AnimInstance：**整套蒙太奇 MPSC 队列**（`FActPendingMontage`、`PlayMontageSafe`/`QueueMontage`/`StopMontagesSafe`、
  `FlushPendingMontages`、`NativeUpdateAnimation` 覆写）—— 0 引用，roll/attack 走 `PlayAnimMontage` 没经过它

**故意保留**：`SetTargetYawAngle` / `SetRotationInterpSpeed`（战斗锁朝向，Phase 6 用）、`GetTurnAngle`（k 与调试用）、
`bPivotRotationFrozen`、pivot 蒙太奇整套（当前唯一可用实现，必须等状态机版本跑通再删）。

**编译验证**：三个 cpp + unity 重编全部无 error。**链接失败是环境问题**：
UBA 本地执行器对所有输出报 `SetFileInformationByHandle (FileDispositionInfo) ... Access is denied`，
把 `.lib`/`.pdb` 写成 0 字节 → `LNK1136 无效或损坏的文件` / `LNK1201`。ALS、VisualStudioTools 同样被清零。
已清掉 11 个 0 字节产物；**`Binaries/Win64/UnrealEditor-ACTGame.dll` 目前缺失，需在 VS 里 Rebuild 恢复**。
教训：不要在受限 shell 里跑 UBT 链接，编译验证用 `-SingleFile` 或只跑 compile 步骤。

## 重构：角色类 + 动画实例去多余逻辑（第三次清理）

**结果**：`AACTCharacterBase` 504 → 489（-15），`UACTAnimInstance` 172 → 116（-56），合计 -71。
三个类从附录 A 起算累计 2133 → 1283（-40%）。

**删除**：
- `UACTAnimInstance` 整套「跨线程朝向通道」：`SetAnimationDrivenYawOffset` / `StopAnimationDrivenYaw` /
  `IsAnimYawDriveActive` / `GetAnimYawDriveOffset` / `GetAnimYawDriveSeq`、3 个 `std::atomic` 字段、`#include <atomic>`。
  死亡路径：写端 ABP 从未接过（`SetAnimationDrivenYawOffset` 在 ABP 名表里根本不存在）→ 中间原子槽 → 读端已随附录 B 删除。
  这个类现在只剩 `Character` / `ACTMovement` 缓存 + `NativeInitializeAnimation` + 两个 BlueprintPure getter。
- `AACTCharacterBase`：`GetCameraBoom()` / `GetFollowCamera()`（Content 无名表，属性本身 BlueprintReadOnly 够用）、
  `GetLocomotionState()`（ABP 用 Property Access 直读，C++ 走引用版）。

**保留（0 引用但删了更糟）**：`SetRotationMode`/`GetRotationMode`（ABP 读 `RotationMode` 名表 4 处，
删 setter 会让 `LookingDirection` 分支永久不可达）、`SetGait`/`GetGait`/`SetStance`/`GetStance`（输入层在用）、
`GetACTMovement`/`GetActCharacter`（ABP 在调）。

**新判定标准（写进文档 C.1）**：0 引用要分三类 —— 冗余层（数据别处可拿，删）、断头通道（生产/消费端已删一半，删）、
未接线功能（代码完整只是资产没配，保留）。补充：`BindAction(nullptr)` 不崩、只生成永不匹配的 binding
（`UEnhancedInputComponent::BindAction` 内联在头文件、无 null 检查），所以"资产没配"≠"代码是死的"。

**资产侧发现**：`BP_PC_01` 里 `JumpAction`/`CrouchAction`/`RollAction`/`WalkAction` **全是 null**，
IMC_Default 里也没有 `IA_Walk`/`IA_Crouch`/`IA_Roll`。所以跳跃/蹲/翻滚/走跑切换当前全是静默失效，
不是 bug 也不是死代码。已赋值的只有 IMC、MoveAction、LookMouseAction、LookAction、SprintAction。
另外 `BP_PC_01` 只被 `BP_ACT_GameMode` 引用，而 `GlobalDefaultGameMode` 指向 `BP_ThirdPersonGameMode`。

**构建终于跑通**：`-NoUBA -NoLinkerDebugInfo` → **Result: Succeeded**，DLL 1,842,688 bytes，PDB 73 MB。
编译 0 error（4 个 cpp）。**关键结论：LNK1136/LNK1201 的根因是 UBA 本地执行器写入被拒
（`SetFileInformationByHandle (FileDispositionInfo) Access is denied`）把 .lib/.pdb 清零，加 `-NoUBA` 即可。**
以后构建失败先看是不是 LNK1136，别改代码。

**待办**：`ABP_PC_01` 若图里有 `StopAnimationDrivenYaw` 节点要删（父类已无此函数）；
`BP_PC_01` 的 `HandlePivotRequested` 孤儿覆盖仍需手工删。
